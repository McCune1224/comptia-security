# Plan: Security+ SY0-701 V3 Anki Flashcards (2026 Refresh)

## Overview

Create **four Anki flashcard decks** as CSV files for the CompTIA Security+ SY0-701 (2026 refresh):
1. **V3 Definitions** — Pure Q&A terminology (~600 cards across 5 domains)
2. **V3 Scenario Practice** — Scenario/PBQ-style application questions (~100 cards)
3. **Ports & Protocols** — Dedicated port memorization deck (~80 cards)
4. **V3 PBQs** — Performance-based question simulations (~50 cards)

The user is a sysadmin returning after a study break — cards are designed for high-retention refresher review, not first-time learning.

## Current State

The vault already has ~1,025 cards across V1 (527 cards, 6 files) and V2 (499 cards, 5 files):
- **V1**: More scenario-based, quoted CSV format (`"Front","Back","Tags"`), includes a Reference deck (ports + acronyms)
- **V2**: More definition-based, simpler CSV format (`Front,Back,Tags`), no separate reference deck
- **Key gap**: Neither covers the 2026 SY0-701 refresh content (AI threats, expanded zero-trust, cloud security evolution, governance for automated tools, passkeys/FIDO2, SBOM/SLSA)

## Recommended Approach

**Why:**
- Pure definition deck = fastest refresher (quick Q&A recall for a sysadmin who knows the concepts)
- Scenario deck = bridges definitions to exam application (tests understanding, not just memorization)
- Separate Ports file = focused port cramming (per user preference)
- PBQ deck = simulates the performance-based questions that trip up most testers

```
Front,Back,Tags
What is the CIA Triad?,Confidentiality Integrity Availability - core security principles,1::Definitions
```

Tags use a simple prefix system:
- `1::Definitions`, `2::Definitions`, etc. for domain definitions
- `Ports::Protocols` for port/protocol cards
- `1::Scenario` through `5::Scenario` for scenario cards
- `PBQ::IncidentResponse`, `PBQ::Architecture`, etc. for PBQ types

### Phase 2: Domain 1 Definitions — General Security Concepts (~55 cards)

- CIA triad + CIANA pentagon
- Security control types (6) and categories (4) with examples
- Zero Trust: control plane vs data plane, PE/PA/PEP, adaptive identity, threat scope reduction
- AAA: authenticating people vs authenticating systems, authorization models
- Gap analysis
- Physical security: bollards, access control vestibule/man-trap, fencing, video surveillance, security guard, access badge, lighting, sensors (IR/pressure/microwave/ultrasonic)
- Deception/disruption: honeypot, honeynet, honeyfile, honeytoken
- Change management: CAB, backout plan, maintenance window, impact analysis, SOPs
- Cryptographic foundations: symmetric vs asymmetric, hashing, salting, PKI components, digital signatures, key exchange (Diffie-Hellman)

### Phase 3: Domain 2 Definitions — Threats, Vulnerabilities, Mitigations (~130 cards)

- Threat actors (7 types + motivations): nation-state, hacktivist, organized crime, insider, script kiddie, APT, shadow IT
- Social engineering: phishing (spear/whaling/vishing/smishing), BEC, pretexting, watering hole, baiting, tailgating, piggybacking, typosquatting, brand impersonation, psychological triggers (authority, urgency, scarcity, social proof, fear, likability)
- Threat vectors: message, image, file, voice call, removable device, unsecured network
- **NEW 2026**: AI-powered attacks — deepfakes, adversarial ML, prompt injection, model poisoning, AI-generated phishing, LLM data leakage, training data poisoning
- Malware: virus, worm, trojan, ransomware (double extortion), rootkit, spyware, keylogger, RAT, botnet, logic bomb, bloatware
- Application attacks: SQLi, NoSQLi, XSS (stored/reflected/DOM), CSRF, SSRF, buffer overflow, integer overflow, race condition (TOC/TOU), directory traversal, command injection
- Password attacks: brute force, dictionary, password spraying, credential stuffing, hybrid
- Network attacks: DoS/DDoS (volumetric/protocol/application), on-path (MITM), replay, downgrade, DNS poisoning, DNS tunneling, ARP spoofing, MAC flooding, DHCP starvation
- Wireless attacks: BlueBorne, BlueSmack, Evil Twin, deauth attack, jamming, RFID cloning, NFC relay
- Supply chain attacks: **NEW 2026** — SBOM, SLSA framework, dependency confusion, typosquatting in packages
- Mitigation: hardening, segmentation (microsegmentation), patching, least privilege, application allowlisting vs blocklisting, encryption, isolation, configuration enforcement, FIM, WAF, HIPS
- IoCs: unusual traffic, impossible travel, account anomalies, database read volume increases

### Phase 4: Domain 3 Definitions — Security Architecture (~80 cards)

- Cloud models: IaaS/PaaS/SaaS, shared responsibility, hybrid, multi-cloud, public/private/community

- Virtualization: Type 1 vs 2 hypervisors, VM escape, resource reuse, snapshot
- Containerization: Docker, orchestration (K8s), container isolation, image signing, registry security

- Serverless: FaaS, event-driven, cold start, function permissions
- Microservices: API gateways, service-to-service auth, mTLS
- Zero Trust (expanded for 2026): ZTNA vs VPN, microsegmentation, identity-aware proxies, continuous verification, device posture checks
- ICS/SCADA: PLC, RTU, HMI, safety systems, air gap
- IoT/Embedded: RTOS, OTA updates, constrained devices, MQTT, CoAP
- SDN: control plane vs data plane vs application plane

### Phase 7: Scenario Practice Deck (~100 cards)

Scenario-based application questions. Each card presents a realistic scenario and asks for the correct action/identification.

- **Domain 1 scenarios (12 cards)**: Identify control type/category from scenario, apply zero trust principles, choose encryption method, classify data
- **Domain 2 scenarios (25 cards)**: Identify attack type from description, choose mitigation, recognize social engineering variant, order incident response phases
- **Domain 3 scenarios (18 cards)**: Recommend architecture, choose DR site type, calculate RTO/RPO from business requirements, select cloud model
- **Domain 4 scenarios (30 cards)**: Interpret SIEM alerts, configure firewall rules, choose IAM solution, select monitoring tool, respond to incidents
- **Domain 5 scenarios (15 cards)**: Calculate SLE/ARO/ALE, identify compliance requirements, choose governance documents, recommend risk response

Format: `Scenario: ... [1-3 sentences]. What should the security analyst do/recommend?` + answer

### Phase 8: PBQ Practice Deck (~50 cards)

Performance-based question simulations. Cards that challenge the "drag and drop" or "order the steps" style of PBQs:

- **Drag-and-order**: Incident response phases, risk management lifecycle, forensic order of volatility, change management process, DORA (DHCP), TLS handshake
- **Matching**: Map port to protocol, control type to example, threat actor to motivation, vulnerability to attack, framework to purpose
- **Light simulation**: "Configure firewall rules to allow X while blocking Y" (abstracted to text), "Select three controls for scenario Z", "Identify which log entries indicate compromise"
- **Calculate**: Given asset value, EF, ARO → calculate ALE. Determine if a control is cost-effective.

Format: `PBQ: [task description]` + answer with explanation

### Phase 9: Validation

1. Run `python3 -c "import csv; [csv.reader(open(f)) for f in glob('*.csv')]"` to validate all CSVs
2. Spot-check 5 cards per file for correctness and format consistency
3. Verify UTF-8 encoding (Anki requires this for special characters)
4. Confirm all cards have non-empty front and back fields
5. Test import with: `anki --import file.csv` (if available)

## Risks & Considerations

- **Content accuracy**: The 2026 refresh is a content update (same exam code SY0-701). Refresh topics (AI threats, passkeys, SBOM, SLSA, CIEM, etc.) are gathered from web research — verify against the official SY0-701 v5.0 objectives PDF before exam day.
- **Card count**: ~775 cards. At 30s/card review, that's ~6.5 hours total review time (spread over days/weeks). Designed for a 1-2 week refresher at 30-60 min/day.
- **V1/V2 kept untouched**: The existing decks remain. V3 is additive. If any V1/V2 cards are superior, they can be merged later.
- **PBQ limitation**: PBQs are inherently interactive (drag/drop, simulation). Text-based PBQ cards can't fully replicate the exam experience — use them for concept recall, then practice on a PBQ simulator (FlashGenius, CertMaster) before exam day.
